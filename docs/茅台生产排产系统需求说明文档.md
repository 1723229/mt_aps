# 茅台生产排产系统需求说明文档

## 1. 系统概述

茅台生产排产系统是面向包装车间的智能排产优化系统，负责在满足各类约束条件下，优化产线、班组、产品的排产方案，实现总产能利用率最大化。

---

## 2. 排产目标

### 2.1 核心目标
在所有计划产品都生产到的前提下(每个产品至少安排一个班次生产)，尽可能提高总产能利用率，完成各产品计划量的生产。

### 2.2 优化指标

#### 2.2.1 总产能利用率最大化
**定义**：
```
总产能利用率 = 每个班次对应产品计划量累加(单位瓶) ÷ 所有计划产品累加(单位瓶) × 100%
```

**目标**：

- 所有场景：每个产品生产不超过计划总量,  所以总产能利用率 <= 100%

**优先级**：

```
所有计划产品都生产到 > 高产能利用率  
```

### 3.2 SchedulePlanDetail（排产计划详情）

| 字段           | 类型  | 说明                           | 备注                     |
| -------------- | ----- | ------------------------------ | ------------------------ |
| baseSpiritCode | str   | 酒质编码（基酒类型）           | 如"MC530001"             |
| baseSpiritName | str   | 酒质名称                       | 如"经典酒质"             |
| productType    | str   | 产品类型                       | 可为null                 |
| productCode    | str   | 产品编码                       | 唯一标识，如"MT0010010082" |
| productName    | str   | 产品名称                       | -                        |
| bottleTotal    | int   | 计划量（瓶）                   | 排产目标产量             |
| plannedTotal   | float | 计划量（吨）                   | -                        |
| orderType      | str   | 订单类型                       | 如"WEEK_PLAN"            |
| bomVer         | float | BOM版本号                      | 可为null                 |
| deliverDay     | str   | 交货日期                       | 可为null，格式"YYYY-MM-DD" |
| spec           | int   | 规格（ml）                     | 如500, 1000              |
| price          | float | 价格                           | -                        |

**重要说明**：

1. **吨数和瓶数换算公式**：
   ```
   bottleTotal = plannedTotal × 500 × 2124 ÷ spec
   
   示例：
   - plannedTotal = 2568.27 吨
   - spec = 500 ml
   - bottleTotal = 2568.27 × 500 × 2124 ÷ 500 = 5,455,005 瓶
   ```

2. **计划量约束**：
   - `bottleTotal` 为排产的目标产量
   - 完成计划目标后，累计生产量不应超过bottleTotal
   - 严禁大幅超量生产

### 3.4 LineProductSettingDetail（产线产品配置）

定义产线可生产的产品及其生产参数：

| 字段               | 类型 | 说明                                   | 使用规则               |
| ------------------ | ---- | -------------------------------------- | ---------------------- |
| lineCode           | str  | 产线编码                               | 如"030206"             |
| lineName           | str  | 产线名称                               | 如"包装6号线"          |
| productCode        | str  | 产品编码                               | -                      |
| productName        | str  | 产品名称                               | -                      |
| standardCapacity   | int  | 标准产能（每班次标准生产瓶数）         | 用于计算利用率         |
| productionCapacity | int  | 排产产能（实际可用产能）               | **优先使用此值排产**   |
| workerNum          | int  | 额定人数                               | 参考信息               |
| standardScore      | int  | 标准工分                               | 参考信息               |
| conversionTime     | int  | 换产时间（分钟）                       | 换产场景参考           |
| scheduleType       | str  | 排班类型                               | 冗余字段，不使用       |
| priority           | int  | 产线产品优先级                         | 冗余字段，不使用       |
| lineProductWeight  | int  | 产线产品权重                           | 冗余字段，不使用       |
| **productLineWeight**  | **int**  | **产品产线权重（数值越小，优先级越高）** | **核心优先级字段** |

**产能使用规则**：
```
1. 排产时优先使用 productionCapacity（考虑实际情况的产能）
2. 若 productionCapacity 为 null 或 0，使用 standardCapacity
3. 计算利用率时始终使用 standardCapacity（标准基准）
```

**优先级规则**：
- **productLineWeight**：产品在该产线的优先级（当产品可在多条产线生产时使用）
- **数值越小，优先级越高**（如：1 > 2 > 3）
- 排产时优先将产品分配到 `productLineWeight` 值小的产线

### 3.5 LineCrewSettingDetail（产线班组配置）

定义产线可使用的班组及其优先级：

| 字段             | 类型 | 说明                     | 使用规则           |
| ---------------- | ---- | ------------------------ | ------------------ |
| lineCode         | str  | 产线编码                 | -                  |
| lineName         | str  | 产线名称                 | -                  |
| crewCode         | str  | 班组编码                 | 如"pack01"         |
| crewName         | str  | 班组名称                 | 如"包装1班"        |
| priority         | int  | 优先级                   | 冗余字段，不使用   |
| lineCrewPriority | int  | 产线班组优先级           | **数值越小优先级越高** |
| crewLinePriority | int  | 班组产线优先级           | **数值越小优先级越高** |

**班组选择规则**：
```
当某产线需要选择班组时：
1. 优先选择 lineCrewPriority 值小的班组（产线对该班组的偏好）
2. 若多个班组优先级相同，选择 crewLinePriority 值小的（班组对该产线的偏好）
3. 若仍相同，选择当前负荷较轻的班组（促进负荷均衡）
```

**说明**：
- 通过 `lineCode` 和 `crewCode` 的组合，定义产线-班组的绑定关系
- 结合产线产品配置，形成**产线-产品-班组**的三方绑定关系

定义各类排产约束规则：

| 字段            | 类型 | 说明       |
| --------------- | ---- | ---------- |
| constraintType  | str  | 约束类型   |
| constraintName  | str  | 约束名称   |
| constraintValue | Any  | 约束规则值 |
| enable          | bool | 是否启用   |
| orderNum        | int  | 排序编号   |

#### 3.6.1 约束类型详解

**当前系统仅考虑以下两种约束类型**：

##### （1）产线不可用时间约束（line_forbid_time）

**功能**：指定产线在特定日期不可生产

**数据结构示例**：
```json
{
    "enable": true,
    "constraintType": "line_forbid_time",
    "constraintName": "产线不可用时间",
    "constraintValue": [
        {
            "lineCode": "030207",
            "forbidTime": "2025-10-10"
        },
        {
            "lineCode": "030207",
            "forbidTime": "2025-10-11"
        }
    ]
}
```

**处理规则**：
```
1. 产线在禁用日期的早班和中班均不可用
2. 该产线对应的班组需分配到其他可用产线
3. 若班组无其他可用产线，允许该班组在该日期空闲（放松"班组全排产"约束）
4. 若产线独占产品无法在其他产线生产，直接报错，要求调整约束
```

**验证规则**：
```
在排产前应验证：
- 产线禁用不会导致独占产品无法生产
- 产线禁用不会导致大量班组无处可去
```

##### （2）产品优先级约束（product_priority）

**功能**：指定产品在特定日期区间必须完成的生产任务量

**数据结构示例**：
```json
{
    "enable": true,
    "constraintType": "product_priority",
    "constraintName": "产品优先级",
    "constraintValue": [
        {
            "productCode": "MT0010010778",
            "productName": "飞天53%vol 500ml贵州茅台酒（带杯）（1×4）",
            "distributePeriod": [
                {
                    "assignDate": ["2025-10-07", "2025-10-08", "2025-10-09", "2025-10-10"],
                    "assignDun": 204.71
                },
                {
                    "assignDate": ["2025-10-26", "2025-10-27", "2025-10-28", "2025-10-29"],
                    "assignDun": 300
                }
            ]
        }
    ]
}
```

**处理规则**：
```
1. 在指定日期区间内，该产品必须完成指定吨数的生产
2. 吨数转换为瓶数公式：瓶数 = 吨数 × 500 × 2124 ÷ spec
3. 若指定吨数超过产品总计划量，以总计划量为准
4. 优先安排有优先级约束的产品
5. 若多个产品存在优先级约束且日期冲突，按约束配置顺序排产
```

**示例计算**：
```
产品: MT0010010778
- spec = 500 ml
- assignDun = 204.71 吨
- assignDate = ["2025-10-07", "2025-10-08", "2025-10-09", "2025-10-10"]

瓶数 = 204.71 × 500 × 2124 ÷ 500 = 434,804 瓶

在10-07到10-10这4天，该产品必须生产至少434,804瓶
```

## 4. 核心约束条件

### 4.1 基础约束

| 编号 | 约束名称 | 约束描述 | 强制性 | 详细说明 |
| ---- | -------- | -------- | ------ | -------- |
| BC-01 | 产线-产品-班组绑定 | 某班组只能在指定产线生产指定产品 | 强制 | 由 `lineProductSettingDetails` 和 `lineCrewSettingDetails` 共同决定 |
| BC-02 | 每日双班次 | 每天各产线生产两个班次（早班、中班） | 强制 | 特殊区域可单班或空线，见4.2节 |
| BC-03 | 班组单班次 | 每个班组每天只能生产一个班次 | 强制 | 不能同时排早班和中班 |
| BC-04 | 班组全排产 | 各班组在生产日历的所有日期都应安排排产 | 强制 | 特殊情况（如产线全禁用）可放松 |
| BC-05 | 计划量约束 | 完成计划目标后不应超量生产 | 强制 | 累计生产量 ≤ bottleTotal |
| BC-06 | 产线独占产品保证 | 仅在一条产线生产的产品必须保证完成 | 强制 | 识别方法：该产品仅在一个lineCode出现 |
| BC-07 | 排产结果完整性 | 所有产品必须安排生产 | 强制 | 输出结果中必须包含所有产品的排产记录 |
| BC-08 | 班组柔性规则 | 产线产品完成后，班组释放或占位 | 强制 | 详见4.1.1节 |
| BC-09 | 产线产品连续性 | 同一产线同一产品必须连续生产 | 强制 | 1. 不能中断后再恢复（非工作日除外） 2. 指定产品在特定日期区间必须完成的生产任务量除外 |
| BC-10 | 换产规则 | 产品完成后允许换产，但有产能限制 | 强制 | 详见4.1.2节 |
| BC-11 | 班组班次规则 | 1  班组在同一周内，固定班次生产，全部早班或全部中班   2 班组跨周，切换班次；上周早班，这周就中班 | 非强制 |  |

#### 4.1.1 班组柔性规则详解（BC-08）

**触发条件**：产线上所有计划产品已生产完

**判断流程**：
```
IF 产线所有计划产品已完成 THEN
    IF 该班组可分配到其他产线 
       AND 其他产线未打双班 
       AND 其他产线有产品未生产完 THEN
        释放班组到其他产线
    ELSE
        留在原产线，安排计划量为0的产品占据班次
    END IF
END IF
```

**说明**：
- "其他产线未打双班"：该产线当前班次只有一个班组在生产
- "其他产线有产品未生产完"：其他产线配置的产品还有未完成的计划量
- "计划量为0的产品"：选择该产线配置的、计划量瓶数最大的产品

**示例**：
```
场景：030206产线的所有产品已完成
班组：pack13
其他可用产线：030207

检查：
- pack13可以在030207生产 ✓
- 030207当前只有pack17（未打双班） ✓
- 030207有产品MT0010010082未完成 ✓

结果：释放pack13到030207
```

#### 4.1.2 换产规则详解（BC-10）

**触发条件**：
- 某产品达到总计划量（bottleTotal）
- 该班次出现：班次计划量 < 标准产能

**换产逻辑**：
```
仅在产品达到总计划量的最后一个班次才允许换产

换产公式（考虑换产时间损耗）：
1. 第一产品使用产能 = 第一产品剩余量
2. 第二产品换产可用产能 = 第二产品标准产能 × （1 - 第一产品剩余量/第一产品标准产能 - 0.1)
3. 第二产品可排产量 = min(第二产品换产可用产能, 第二产品剩余计划量)
4. 班次总计划量 = 第一产品剩余量 + 第二产品可排产量
5. 优先考虑同酒质换产 baseSpiritCode -  酒质编码（基酒类型）
```

**换产时间损耗说明**：
- 换产需要时间（清洗、调整设备、换模等）
- 10%的产能损耗用于换产准备时间
- 确保不超产：班次总产量 ≤ 标准产能



**重要说明**：
- 换产时，第一产品只生产剩余量（完成该产品）
- 剩余产能的90%可用于第二产品（10%用于换产准备）
- 一个班次最多换产一次（最多生产2个产品）
- 换产不允许超产：班次总产量不超过标准产能
-

### 4.3 产品优先级约束

#### 4.3.1 产品分配策略

| 场景                   | 排产策略                                                     | 优先级 |
| ---------------------- | ------------------------------------------------------------ | ------ |
| 产品仅在单条产线生产   | 必须在该产线排产，保证生产                                   | 最高   |
| 产品有优先级约束       | 优先满足 `product_priority` 约束，在指定日期完成指定吨数    | 高     |
| 产品在多条产线生产     | 优先分配到 `productLineWeight` 值小的产线（权重越高）       | 中     |
| 高优先级产线已排满     | 考虑分配到优先级低的产线（如该产线未排满）                   | 低     |
| 所有可用产线均已排满   | 安排计划量为0的产品占据班次（选择该产线配置的、bottleTotal最大的产品） | 最低   |

#### 4.3.2 产品生产顺序规则

**同一产线多个产品的生产顺序**：
```
优先级排序：
1. 有 product_priority 约束的产品优先
2. 计划量为0的产品最后排
```


#### 4.3.3 多产线竞争处理

**当产品可在多条产线生产时**：
```
策略1：优先分配到高优先级产线
- 按 productLineWeight 从小到大尝试分配
- 高优先级产线优先获得该产品

策略2：允许多线并行生产（提高效率）
- 若高优先级产线产能不足以完成计划量
- 可同时在多条产线生产该产品
- 但各线必须满足生产连续性
- 总产量不超过 bottleTotal

策略3：降级分配
- 若高优先级产线已排满
- 尝试分配到次优先级产线
- 若所有产线已满，等待产线空闲
```

**示例**：
```
产品: MT0010010082
可生产产线及优先级:
- 030205: productLineWeight=1 (最高优先级)
- 030208: productLineWeight=2
- 030210: productLineWeight=3

分配逻辑:
1. 优先在030205生产
2. 若030205产能不足，同时在030208生产
3. 若030205和030208都满，考虑030210
4. 各产线独立连续生产，互不干扰
```

### 4.4 空线约束

**原则**：产线不能无限制空线（停线不生产）

**规则**：
```
1. 独占产品保护：
   - 必须保证独占产品完成生产

2. 区域空线限制：
   - 老包装区间：每班次必有1条线空闲（结构性）
   - 新包装A区：同一班次最多1条线空线
   - 新包装B区：不允许空线（2条线必须打双班）
   - 新包装C、D区：允许部分线空线，但需维持"2双2单"

3. 产线禁用与空线的区别：
   - 产线禁用：强制约束，该日期完全不可用
   - 产线空线：排产结果，该班次无产品班组安排
   - 产线禁用会触发空线，但空线不一定是禁用导致

4. 空线判断逻辑：
   - 若产线有独占产品未完成，不允许空线
   - 若产线所有产品已完成，允许空线
   - 若班组可释放到其他产线，优先释放，避免空线
```

## 5. 业务规则细化

### 5.1 产能计算规则

#### 5.1.1 班次产能选择
```
1. 排产时优先使用 productionCapacity（考虑实际情况的产能）
2. 若 productionCapacity 为 null 或 0，使用 standardCapacity
3. 计算利用率时始终使用 standardCapacity（标准基准）
```

#### 5.1.2 利用率计算
```
利用率 = 班次计划量 ÷ 标准产能 × 100%

注意：
- 始终使用 standardCapacity 作为基准
- 所有情况：利用率 ≤ 100%（严禁超产）
- 换产损耗：10%产能用于换产准备
```

#### 
### 5.2 产品生产完成判断

#### 5.2.1 完成判断规则
```
判断条件：
累计生产量 = 计划量

```

#### 5.2.2 产品完成后处理
```
流程：
1. 标记产品为"已完成"状态
2. 检查产线是否还有其他未完成产品
3. IF 有其他未完成产品 THEN
     立即换产到下一个产品
   ELSE
     触发班组柔性规则（BC-08）
   END IF
```

### 5.3 班组分配规则

#### 5.3.1 班组选择优先级
```
当某产线需要选择班组时，按以下顺序：
1. 第一优先级：lineCrewPriority 值小的（产线对班组的偏好）
2. 第二优先级：crewLinePriority 值小的（班组对产线的偏好）
3. 第三优先级：当前负荷较轻的班组（促进负荷均衡）
```

#### 5.3.2 班组可用性判断
```
班组可用条件（必须全部满足）：
1. 该班组当天尚未排产（满足BC-03单班次约束）
2. 该班组在该产线的配置中（满足BC-01绑定约束）
3. 对于老包装区间，需检查固定搭配规则
4. 班组未被其他产线占用（同一班次）
```

### 5.4 产线分配规则

#### 5.4.1 产品-产线匹配
```
获取产品可用产线列表：
1. 查找所有配置该产品的产线
2. 按 productLineWeight 从小到大排序
3. 返回排序后的产线列表
```

#### 5.4.2 产线选择策略
```
按优先级依次检查可用产线：
1. 检查：产线是否禁用（line_forbid_time约束）
2. 检查：产线是否已满（双班都已安排）
3. 检查：产线是否有可用班组
4. 检查：是否满足区域特殊约束
5. 选择第一个通过所有检查的产线
```

### 5.5 计划量为0的产品安排

#### 5.5.1 选择规则
```
选择标准（优先级从高到低）：
1. 必须是该产线配置的产品
2. 选择该产线计划量瓶数最大的产品
3. 若瓶数相同，选择 productLineWeight 值最小的
4. 目的：占据班次，避免班组空闲
```

#### 5.5.2 安排条件
```
触发条件（必须全部满足）：
1. 产线所有有计划产品已完成
2. 班组无法释放到其他产线
3. 班组必须排产（满足BC-04约束）

```
