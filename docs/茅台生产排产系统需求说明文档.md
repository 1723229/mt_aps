# 茅台生产排产系统需求说明文档

## 1. 系统概述

茅台生产排产系统是面向包装车间的智能排产优化系统，负责在满足各类约束条件下，优化产线、班组、产品的排产方案，实现产能利用率最大化。

---

## 2. 排产目标

### 2.1 核心目标
在所有计划产品都生产的前提下，尽可能提高产能利用率，完成各产品计划量的生产。

### 2.2 优化指标

#### 2.2.1 产能利用率最大化
**定义**：
```
班次产能利用率 = 班次计划量 ÷ 标准产能 × 100%
```

**目标**：
- 正常生产：利用率目标 85% ~ 100%
- 换产场景：考虑换产损耗，利用率通常 60% ~ 90%
- 排产周期平均利用率 ≥ 85%
- 所有场景：利用率不超过 100%（严禁超产）

**优先级**：
```
完成所有产品 > 高产能利用率 > 班组负荷均衡
```

#### 2.2.2 班组工作负荷均衡
**定义**：
```
班组负荷 = Σ(各班次计划量 ÷ 各班次标准产能)
均衡度 = max(班组负荷) - min(班组负荷)
```

**目标**：
- 均衡度 < 15%
- 各班组总生产量差异 ≤ 20%
- 各班组平均利用率差异 ≤ 10%

### 3.2 SchedulePlanDetail（排产计划详情）

| 字段           | 类型  | 说明                           | 备注                     |
| -------------- | ----- | ------------------------------ | ------------------------ |
| baseSpiritCode | str   | 酒质编码（基酒类型）           | 如"MC530001"             |
| baseSpiritName | str   | 酒质名称                       | 如"经典酒质"             |
| productType    | str   | 产品类型                       | 可为null                 |
| productCode    | str   | 产品编码                       | 唯一标识，如"MT0010010082" |
| productName    | str   | 产品名称                       | -                        |
| bottleTotal    | int   | 计划量（瓶）                   | 排产目标产量             |
| plannedTotal   | float | 计划量（吨）                   | -                        |
| orderType      | str   | 订单类型                       | 如"WEEK_PLAN"            |
| bomVer         | float | BOM版本号                      | 可为null                 |
| deliverDay     | str   | 交货日期                       | 可为null，格式"YYYY-MM-DD" |
| spec           | int   | 规格（ml）                     | 如500, 1000              |
| price          | float | 价格                           | -                        |

**重要说明**：

1. **吨数和瓶数换算公式**：
   ```
   bottleTotal = plannedTotal × 500 × 2124 ÷ spec
   
   示例：
   - plannedTotal = 2568.27 吨
   - spec = 500 ml
   - bottleTotal = 2568.27 × 500 × 2124 ÷ 500 = 5,455,005 瓶
   ```

2. **计划量约束**：
   - `bottleTotal` 为排产的目标产量
   - 完成计划目标后，累计生产量不应超过 `bottleTotal × 1.01`（允许1%误差）
   - 严禁大幅超量生产

3. **计划量为0的产品**：
   - `bottleTotal = 0` 的产品可安排占据班次
   - 仅在该产线所有有计划产品（bottleTotal > 0）已完成时才能安排
   - 选择规则：优先选择该产线配置的、bottleTotal最大的产品（虽然当前为0，但可参考历史计划量）

### 3.4 LineProductSettingDetail（产线产品配置）

定义产线可生产的产品及其生产参数：

| 字段               | 类型 | 说明                                   | 使用规则               |
| ------------------ | ---- | -------------------------------------- | ---------------------- |
| lineCode           | str  | 产线编码                               | 如"030206"             |
| lineName           | str  | 产线名称                               | 如"包装6号线"          |
| productCode        | str  | 产品编码                               | -                      |
| productName        | str  | 产品名称                               | -                      |
| standardCapacity   | int  | 标准产能（每班次标准生产瓶数）         | 用于计算利用率         |
| productionCapacity | int  | 排产产能（实际可用产能）               | **优先使用此值排产**   |
| workerNum          | int  | 额定人数                               | 参考信息               |
| standardScore      | int  | 标准工分                               | 参考信息               |
| conversionTime     | int  | 换产时间（分钟）                       | 换产场景参考           |
| scheduleType       | str  | 排班类型                               | 冗余字段，不使用       |
| priority           | int  | 产线产品优先级                         | 冗余字段，不使用       |
| lineProductWeight  | int  | 产线产品权重                           | 冗余字段，不使用       |
| **productLineWeight**  | **int**  | **产品产线权重（数值越小，优先级越高）** | **核心优先级字段** |

**产能使用规则**：
```
1. 排产时优先使用 productionCapacity（考虑实际情况的产能）
2. 若 productionCapacity 为 null 或 0，使用 standardCapacity
3. 计算利用率时始终使用 standardCapacity（标准基准）
```

**优先级规则**：
- **productLineWeight**：产品在该产线的优先级（当产品可在多条产线生产时使用）
- **数值越小，优先级越高**（如：1 > 2 > 3）
- 排产时优先将产品分配到 `productLineWeight` 值小的产线

### 3.5 LineCrewSettingDetail（产线班组配置）

定义产线可使用的班组及其优先级：

| 字段             | 类型 | 说明                     | 使用规则           |
| ---------------- | ---- | ------------------------ | ------------------ |
| lineCode         | str  | 产线编码                 | -                  |
| lineName         | str  | 产线名称                 | -                  |
| crewCode         | str  | 班组编码                 | 如"pack01"         |
| crewName         | str  | 班组名称                 | 如"包装1班"        |
| priority         | int  | 优先级                   | 冗余字段，不使用   |
| lineCrewPriority | int  | 产线班组优先级           | **数值越小优先级越高** |
| crewLinePriority | int  | 班组产线优先级           | **数值越小优先级越高** |

**班组选择规则**：
```
当某产线需要选择班组时：
1. 优先选择 lineCrewPriority 值小的班组（产线对该班组的偏好）
2. 若多个班组优先级相同，选择 crewLinePriority 值小的（班组对该产线的偏好）
3. 若仍相同，选择当前负荷较轻的班组（促进负荷均衡）
```

**说明**：
- 通过 `lineCode` 和 `crewCode` 的组合，定义产线-班组的绑定关系
- 结合产线产品配置，形成**产线-产品-班组**的三方绑定关系

### 3.6 ConstraintSetting（约束配置）

定义各类排产约束规则：

| 字段            | 类型 | 说明       |
| --------------- | ---- | ---------- |
| constraintType  | str  | 约束类型   |
| constraintName  | str  | 约束名称   |
| constraintValue | Any  | 约束规则值 |
| enable          | bool | 是否启用   |
| orderNum        | int  | 排序编号   |

#### 3.6.1 约束类型详解

**当前系统仅考虑以下两种约束类型**：

##### （1）产线不可用时间约束（line_forbid_time）

**功能**：指定产线在特定日期不可生产

**数据结构示例**：
```json
{
    "enable": true,
    "constraintType": "line_forbid_time",
    "constraintName": "产线不可用时间",
    "constraintValue": [
        {
            "lineCode": "030207",
            "forbidTime": "2025-10-10"
        },
        {
            "lineCode": "030207",
            "forbidTime": "2025-10-11"
        }
    ]
}
```

**处理规则**：
```
1. 产线在禁用日期的早班和中班均不可用
2. 该产线对应的班组需分配到其他可用产线
3. 若班组无其他可用产线，允许该班组在该日期空闲（放松"班组全排产"约束）
4. 若产线独占产品无法在其他产线生产，直接报错，要求调整约束
```

**验证规则**：
```
在排产前应验证：
- 产线禁用不会导致独占产品无法生产
- 产线禁用不会导致大量班组无处可去
```

##### （2）产品优先级约束（product_priority）

**功能**：指定产品在特定日期区间必须完成的生产任务量

**数据结构示例**：
```json
{
    "enable": true,
    "constraintType": "product_priority",
    "constraintName": "产品优先级",
    "constraintValue": [
        {
            "productCode": "MT0010010778",
            "productName": "飞天53%vol 500ml贵州茅台酒（带杯）（1×4）",
            "distributePeriod": [
                {
                    "assignDate": ["2025-10-07", "2025-10-08", "2025-10-09", "2025-10-10"],
                    "assignDun": 204.71
                },
                {
                    "assignDate": ["2025-10-26", "2025-10-27", "2025-10-28", "2025-10-29"],
                    "assignDun": 300
                }
            ]
        }
    ]
}
```

**处理规则**：
```
1. 在指定日期区间内，该产品必须完成指定吨数的生产
2. 吨数转换为瓶数公式：瓶数 = 吨数 × 500 × 2124 ÷ spec
3. 若指定吨数超过产品总计划量，以总计划量为准
4. 优先安排有优先级约束的产品
5. 若多个产品存在优先级约束且日期冲突，按约束配置顺序排产
```

**示例计算**：
```
产品: MT0010010778
- spec = 500 ml
- assignDun = 204.71 吨
- assignDate = ["2025-10-07", "2025-10-08", "2025-10-09", "2025-10-10"]

瓶数 = 204.71 × 500 × 2124 ÷ 500 = 434,804 瓶

在10-07到10-10这4天，该产品必须生产至少434,804瓶
```

## 4. 核心约束条件

### 4.1 基础约束（强制）

| 编号 | 约束名称 | 约束描述 | 强制性 | 详细说明 |
| ---- | -------- | -------- | ------ | -------- |
| BC-01 | 产线-产品-班组绑定 | 某班组只能在指定产线生产指定产品 | 强制 | 由 `lineProductSettingDetails` 和 `lineCrewSettingDetails` 共同决定 |
| BC-02 | 每日双班次 | 每天各产线生产两个班次（早班、中班） | 强制 | 特殊区域可单班或空线，见4.2节 |
| BC-03 | 班组单班次 | 每个班组每天只能生产一个班次 | 强制 | 不能同时排早班和中班 |
| BC-04 | 班组全排产 | 各班组在生产日历的所有日期都应安排排产 | 强制 | 特殊情况（如产线全禁用）可放松 |
| BC-05 | 计划量约束 | 完成计划目标后不应超量生产 | 强制 | 累计生产量 ≤ bottleTotal × 1.01 |
| BC-06 | 产线独占产品保证 | 仅在一条产线生产的产品必须保证完成 | 强制 | 识别方法：该产品仅在一个lineCode出现 |
| BC-07 | 排产结果完整性 | 所有产品必须安排生产 | 强制 | 输出结果中必须包含所有产品的排产记录 |
| BC-08 | 班组柔性规则 | 产线产品完成后，班组释放或占位 | 强制 | 详见4.1.1节 |
| BC-09 | 产线产品连续性 | 同一产线同一产品必须连续生产 | 强制 | 不能中断后再恢复（非工作日除外） |
| BC-10 | 换产规则 | 产品完成后允许换产，但有产能限制 | 强制 | 详见4.1.2节 |

#### 4.1.1 班组柔性规则详解（BC-08）

**触发条件**：产线上所有计划产品（bottleTotal > 0）已生产完

**判断流程**：
```
IF 产线所有计划产品已完成 THEN
    IF 该班组可分配到其他产线 
       AND 其他产线未打双班 
       AND 其他产线有产品未生产完 THEN
        释放班组到其他产线
    ELSE
        留在原产线，安排计划量为0的产品占据班次
    END IF
END IF
```

**说明**：
- "其他产线未打双班"：该产线当前班次只有一个班组在生产
- "其他产线有产品未生产完"：其他产线配置的产品还有未完成的计划量
- "计划量为0的产品"：选择该产线配置的、计划量瓶数最大的产品

**示例**：
```
场景：030206产线的所有产品已完成
班组：pack13
其他可用产线：030207

检查：
- pack13可以在030207生产 ✓
- 030207当前只有pack17（未打双班） ✓
- 030207有产品MT0010010082未完成 ✓

结果：释放pack13到030207
```

#### 4.1.2 换产规则详解（BC-10）

**触发条件**：
- 某产品达到总计划量（bottleTotal）
- 该班次出现：班次计划量 < 标准产能

**换产逻辑**：
```
仅在产品达到总计划量的最后一个班次才允许换产

换产公式（考虑换产时间损耗）：
1. 第一产品使用产能 = 第一产品剩余量
2. 换产可用产能 = (标准产能 - 第一产品剩余量) × 0.9
3. 第二产品可排产量 = min(换产可用产能, 第二产品剩余计划量)
4. 班次总计划量 = 第一产品剩余量 + 第二产品可排产量
```

**换产时间损耗说明**：
- 换产需要时间（清洗、调整设备、换模等）
- 用 0.9 系数表示：剩余产能的90%可用于生产第二产品
- 10%的产能损耗用于换产准备时间
- 确保不超产：班次总产量 ≤ 标准产能

**实际案例**：
```
2025-10-22早班, 030204产线, pack04班组:

产品1（完成中）: MT0010010789
- 标准产能: 14000 瓶
- 剩余量: 1 瓶

产品2（开始生产）: MT0010010747
- 标准产能: 15200 瓶（注：此处使用第二产品的标准产能作为基准）
- 产品2剩余计划量: 9193 瓶

计算过程：
1. 第一产品使用产能: 1 瓶
2. 剩余产能: 15200 - 1 = 15199 瓶
3. 换产可用产能: 15199 × 0.9 = 13679 瓶
4. 第二产品可排产量: min(13679, 9193) = 9193 瓶
5. 班次总计划量: 1 + 9193 = 9194 瓶

验证：
- 班次总量 9194 ≤ 标准产能 15200 ✓ (未超产)
- 考虑了换产时间损耗 ✓

产能利用率：
9194 ÷ 15200 = 60.5%
```

**重要说明**：
- 换产时，第一产品只生产剩余量（完成该产品）
- 剩余产能的90%可用于第二产品（10%用于换产准备）
- 一个班次最多换产一次（最多生产2个产品）
- 换产不允许超产：班次总产量不超过标准产能
- 换产以第二产品的标准产能为基准计算可用产能

### 4.2 区域特殊约束

#### 4.2.1 老包装区间（A类约束）

**产线配置**：
- 产线：030201（1号线）、030202（2号线）、030210（10号线）
- 班组：pack01、pack02、pack10、pack14

**双班搭配规则**：
```
固定搭配（不可拆分）：
- 配对1: pack01 + pack02
- 配对2: pack10 + pack14

排班模式：
- 3条线，4个班组（2对搭配）
- 每个班次必有1条产线空闲
```

**约束特征**：
- **双班组固定搭配**：pack01必须与pack02搭配，pack10必须与pack14搭配
- **每班次一线空闲**：3条线对应2对班组，必然有1条线空闲
- 班组搭配不能拆分，必须同时出现

**排产示例**：
```
2025-10-09:
早班: 030201(pack02), 030202(空闲), 030210(pack14)
中班: 030201(pack01), 030202(空闲), 030210(pack10)

或:
早班: 030201(pack02), 030202(pack14), 030210(空闲)
中班: 030201(pack01), 030202(pack10), 030210(空闲)
```

#### 4.2.2 新包装区间A区（B类约束）

**产线配置**：
- 产线：030203（3号线）、030204（4号线）、030207（7号线）、030211（11号线）
- 班组：pack03、pack04、pack07、pack15、pack17
- **特殊规则**：030204不分配pack17

**柔性排班规则**：
```
无固定双班搭配，允许：
- 部分线打双班
- 部分线单班
- 部分线空线

但禁止：
- 同一班次，2条及以上产线同时空线（避免班组无线可去）
```

**约束特征**：
```
1. 班组可灵活分配到各产线
2. 优先安排双班（提高产能利用率）
3. 产品完成后释放班组到其他产线
4. 关键约束：同一班次最多1条线空闲
```

**排产示例**：
```
合法排产：
早班: 030203(pack03+pack15), 030204(pack04), 030207(空闲), 030211(pack07)
     - 2条双班，1条单班，1条空线 ✓

非法排产：
早班: 030203(pack03), 030204(空闲), 030207(空闲), 030211(pack15)
     - 2条空线同时出现 ✗
```

- 产线：030205（5号线）、030206（6号线）
- 班组配置：

1. 产线-班组绑定严格：

2. 排班模式：
   - 两条产线均打双班

3. 5号线专属产品：

**排产示例**：

#### 4.2.4 新包装区间C区、D区（D类约束）

**产线配置**：
- 产线：030208（8号线）、030209（9号线）、030212（12号线）、030213（13号线）
- 班组配置：
  - 030208 ↔ pack08、pack09
  - 030209 ↔ pack08、pack09、pack12、pack18、pack19
  - 030212 ↔ pack18、pack19
  - 030213 ↔ pack12、pack16、pack08、pack09

**双班配置规则**：
```
4条线必须满足：
- 2条线生产双班
- 2条线生产单班
- 不允许3条双班1条单班，或1条双班3条单班

判断方法：
统计各产线的班组数，必须有2条线为2个班组
```

**约束特征**：
```
1. 班组可在多条产线生产（灵活性高）
2. 必须维持"2双2单"的平衡
3. 班组分配受产线-班组匹配关系约束
```

**排产示例**：
```
合法排产：
早班: 030208(pack08+pack09), 030209(pack18+pack19), 030212(空闲), 030213(pack12)
     - 2条双班，1条单班，1条空线 ✓

非法排产：
早班: 030208(pack08+pack09), 030209(pack18+pack19), 030212(pack19), 030213(pack12)
     - 3条线都有班组，但只有2条双班 ✗（应该是2双2单或2双1单1空）
```

### 4.3 产品优先级约束

#### 4.3.1 产品分配策略

| 场景                   | 排产策略                                                     | 优先级 |
| ---------------------- | ------------------------------------------------------------ | ------ |
| 产品仅在单条产线生产   | 必须在该产线排产，保证生产                                   | 最高   |
| 产品有优先级约束       | 优先满足 `product_priority` 约束，在指定日期完成指定吨数    | 高     |
| 产品在多条产线生产     | 优先分配到 `productLineWeight` 值小的产线（权重越高）       | 中     |
| 高优先级产线已排满     | 考虑分配到优先级低的产线（如该产线未排满）                   | 低     |
| 所有可用产线均已排满   | 安排计划量为0的产品占据班次（选择该产线配置的、bottleTotal最大的产品） | 最低   |

#### 4.3.2 产品生产顺序规则

**同一产线多个产品的生产顺序**：
```
优先级排序：
1. 有 product_priority 约束的产品优先
2. 有交货日期（deliverDay）的产品优先
3. 按 deliverDay 从早到晚排序
4. 无交货日期的按 bottleTotal 从大到小排序（先生产大计划量）
5. 计划量为0的产品最后排
```

**示例**：
```
产线030208配置的产品：
产品A: deliverDay="2025-10-15", bottleTotal=100000
产品B: deliverDay="2025-10-20", bottleTotal=200000
产品C: deliverDay=null, bottleTotal=150000
产品D: deliverDay=null, bottleTotal=50000
产品E: bottleTotal=0

生产顺序：
1. 产品A（交货日期最早）
2. 产品B（交货日期次早）
3. 产品C（无交货日期，计划量大）
4. 产品D（无交货日期，计划量小）
5. 产品E（计划量为0，最后）
```

#### 4.3.3 多产线竞争处理

**当产品可在多条产线生产时**：
```
策略1：优先分配到高优先级产线
- 按 productLineWeight 从小到大尝试分配
- 高优先级产线优先获得该产品

策略2：允许多线并行生产（提高效率）
- 若高优先级产线产能不足以完成计划量
- 可同时在多条产线生产该产品
- 但各线必须满足生产连续性
- 总产量不超过 bottleTotal × 1.01

策略3：降级分配
- 若高优先级产线已排满
- 尝试分配到次优先级产线
- 若所有产线已满，等待产线空闲
```

**示例**：
```
产品: MT0010010082
可生产产线及优先级:
- 030205: productLineWeight=1 (最高优先级)
- 030208: productLineWeight=2
- 030210: productLineWeight=3

分配逻辑:
1. 优先在030205生产
2. 若030205产能不足，同时在030208生产
3. 若030205和030208都满，考虑030210
4. 各产线独立连续生产，互不干扰
```

### 4.4 空线约束

**原则**：产线不能无限制空线（停线不生产）

**规则**：
```
1. 独占产品保护：
   - 对于仅在该产线生产的产品，产线不能空线
   - 必须保证独占产品完成生产

2. 区域空线限制：
   - 老包装区间：每班次必有1条线空闲（结构性）
   - 新包装A区：同一班次最多1条线空线
   - 新包装B区：不允许空线（2条线必须打双班）
   - 新包装C、D区：允许部分线空线，但需维持"2双2单"

3. 产线禁用与空线的区别：
   - 产线禁用：强制约束，该日期完全不可用
   - 产线空线：排产结果，该班次无班组安排
   - 产线禁用会触发空线，但空线不一定是禁用导致

4. 空线判断逻辑：
   - 若产线有独占产品未完成，不允许空线
   - 若产线所有产品已完成，允许空线
   - 若班组可释放到其他产线，优先释放，避免空线
```

## 5. 业务规则细化

### 5.1 产能计算规则

#### 5.1.1 班次产能选择
```
1. 排产时优先使用 productionCapacity（考虑实际情况的产能）
2. 若 productionCapacity 为 null 或 0，使用 standardCapacity
3. 计算利用率时始终使用 standardCapacity（标准基准）
```

#### 5.1.2 利用率计算
```
利用率 = 班次计划量 ÷ 标准产能 × 100%

注意：
- 始终使用 standardCapacity 作为基准
- 所有情况：利用率 ≤ 100%（严禁超产）
- 换产情况：由于换产损耗，利用率通常 60% ~ 90%
- 换产损耗：10%产能用于换产准备，体现在0.9系数中
```

#### 5.1.3 换产产能验证
```
换产验证公式（考虑换产时间损耗）：
1. 换产可用产能 = (标准产能 - 第一产品剩余量) × 0.9
2. 第二产品可排产量 = min(换产可用产能, 第二产品剩余计划量)
3. 班次总计划量 = 第一产品剩余量 + 第二产品可排产量
4. 验证：班次总计划量 ≤ 标准产能

说明：
- 第一产品：达到总计划量的产品，只生产剩余量
- 第二产品：新开始生产的产品
- 以第二产品的标准产能为基准计算
- 0.9系数：考虑换产时间损耗（10%产能用于换产准备）
- 不允许超产：班次总产量不超过标准产能
```

### 5.2 产品生产完成判断

#### 5.2.1 完成判断规则
```
判断条件：
累计生产量 ≥ 计划量 × 99%

说明：
- 允许1%的误差范围
- 累计生产量 ≤ 计划量 × 101%（防止超量）
```

#### 5.2.2 产品完成后处理
```
流程：
1. 标记产品为"已完成"状态
2. 检查产线是否还有其他未完成产品
3. IF 有其他未完成产品 THEN
     立即换产到下一个产品
   ELSE
     触发班组柔性规则（BC-08）
   END IF
```

### 5.3 班组分配规则

#### 5.3.1 班组选择优先级
```
当某产线需要选择班组时，按以下顺序：
1. 第一优先级：lineCrewPriority 值小的（产线对班组的偏好）
2. 第二优先级：crewLinePriority 值小的（班组对产线的偏好）
3. 第三优先级：当前负荷较轻的班组（促进负荷均衡）
```

#### 5.3.2 班组可用性判断
```
班组可用条件（必须全部满足）：
1. 该班组当天尚未排产（满足BC-03单班次约束）
2. 该班组在该产线的配置中（满足BC-01绑定约束）
3. 对于老包装区间，需检查固定搭配规则
4. 班组未被其他产线占用（同一班次）
```

### 5.4 产线分配规则

#### 5.4.1 产品-产线匹配
```
获取产品可用产线列表：
1. 查找所有配置该产品的产线
2. 按 productLineWeight 从小到大排序
3. 返回排序后的产线列表
```

#### 5.4.2 产线选择策略
```
按优先级依次检查可用产线：
1. 检查：产线是否禁用（line_forbid_time约束）
2. 检查：产线是否已满（双班都已安排）
3. 检查：产线是否有可用班组
4. 检查：是否满足区域特殊约束
5. 选择第一个通过所有检查的产线
```

### 5.5 计划量为0的产品安排

#### 5.5.1 选择规则
```
选择标准（优先级从高到低）：
1. 必须是该产线配置的产品
2. 选择该产线计划量瓶数最大的产品
3. 若瓶数相同，选择 productLineWeight 值最小的
4. 目的：占据班次，避免班组空闲
```

#### 5.5.2 安排条件
```
触发条件（必须全部满足）：
1. 产线所有有计划产品（bottleTotal > 0）已完成
2. 班组无法释放到其他产线
3. 班组必须排产（满足BC-04约束）

处理方式：
- 安排标准产能的生产量
- 标记为"占位班次"
- 利用率按0%计算（不影响考核）
- 实际不计入产品完成量统计

输出格式：
- 状态字段：标记为"占位"
- 班次计划量：0 或标准产能
- 累计完成量：0
- 产能利用率：0%（不计入考核）
- 该班组继续占位直到排产周期结束
```

### 5.6 连续性保证规则

#### 5.6.1 连续性定义
```
产品在同一产线生产时，生产日期必须连续，即：
- 开始生产后，每个工作日都应继续生产
- 直到产品完成，不能中断
- 非工作日（休息日）不计入中断

判断方法：
检查生产记录中两个生产日期之间是否存在工作日未生产
```

#### 5.6.2 连续性维护策略
```
策略：
1. 产品开始生产后，持续安排到完成
2. 不允许中途切换到其他产品，再切回来
3. 非工作日（周末、节假日）自然中断，不违反连续性
4. 换产不违反连续性（发生在最后一个班次）
```

#### 5.6.3 跨周排产处理
```
规则：
1. 产品生产可以跨周（非工作日自然中断）
2. 但在工作日内必须连续生产
3. 不能今天生产，明天停，后天再生产
4. 周次仅用于统计，不影响排产逻辑
```

### 5.7 班组负荷均衡规则

#### 5.7.1 负荷计算方法
```
班组负荷 = Σ(各班次计划量 ÷ 各班次标准产能)

说明：
- 累加该班组所有排产班次的利用率
- 数值越大，表示负荷越重
```

#### 5.7.2 均衡度评估标准
```
均衡度 = (最大负荷 - 最小负荷) / 平均负荷 × 100%

目标：
- 均衡度 < 15%
- 最大负荷与最小负荷差距不超过平均负荷的15%

评估指标：
- 总生产量均衡：各班组总生产瓶数差异 ≤ 20%
- 利用率均衡：各班组平均利用率差异 ≤ 10%
```

## 6. 异常处理机制

### 6.1 计划无法完成

#### 6.1.1 识别方法
```
产能充足性验证：
总计划量 = Σ(所有产品的 bottleTotal，其中 bottleTotal > 0)
总可用产能 = Σ(所有工作日 × 所有可用产线 × 日产能 × 2班)

产能利用率 = 总计划量 ÷ 总可用产能

判断标准（考虑换产损耗）：
- 产能利用率 > 100%：错误，产能严重不足
- 产能利用率 90%-100%：警告，产能紧张（需考虑换产10%损耗）
- 产能利用率 < 90%：正常
```

#### 6.1.2 处理策略
```
产能利用率 > 100%：
- 直接报错，拒绝排产
- 要求调整：增加工作日、减少计划量、或增加产线
- 输出无法完成的产品清单

产能利用率 90%-100%：
- 发出警告，但尝试排产
- 说明：考虑换产有10%损耗，实际可用产能约90%
- 优先保证独占产品
- 优先保证有 product_priority 约束的产品
- 其他产品按优先级尽量完成
- 输出可能无法完成的产品清单

无法完成的产品处理：
- 标记状态为"部分完成"
- 记录完成比例
- 输出预警报告
```

### 6.2 班组资源冲突

#### 6.2.1 场景1：班组无线可去

**触发条件**：
- 所有可用产线已满或禁用
- 班组在该日期无产线可分配

**处理策略**：
```
1. 尝试调整已有排产（释放其他产线的班组）
2. 若无法调整，放松BC-04约束
3. 允许该班组该日期空闲
4. 记录异常：班组编码、空闲日期、原因
5. 输出警告信息
```

#### 6.2.2 场景2：固定搭配班组冲突

**触发条件**（老包装区间）：
- pack01与pack02无法同时分配
- pack10与pack14无法同时分配

**处理策略**：
```
1. 检查是否有产线禁用导致
2. 若是禁用，要求调整禁用配置
3. 若是产能分配问题，重新调整产品分配
4. 保证固定搭配完整性（不可拆分）
5. 若无法满足，报错提示
```

### 6.3 产线禁用影响

#### 6.3.1 识别方法
```
验证产线禁用合法性：
对于每个 line_forbid_time 约束：
1. 获取被禁用的产线
2. 查找该产线的独占产品
3. 检查独占产品是否能在其他日期完成

若检测到独占产品无法完成，记录异常
```

#### 6.3.2 处理策略
```
1. 排产前验证产线禁用合法性
2. 若检测到独占产品冲突：
   - 直接报错，拒绝排产
   - 提示用户调整产线禁用日期
   - 或为独占产品配置其他产线
3. 不允许强行排产（会导致产品无法完成）
```

### 6.4 约束冲突解决

#### 6.4.1 常见冲突类型
```
冲突1：产品优先级 vs 产能不足
- 多个产品都有 product_priority 约束
- 指定日期区间重叠
- 产能无法同时满足

冲突2：产线禁用 vs 班组全排产
- 产线禁用导致班组无处可去
- BC-04约束无法满足

冲突3：固定搭配 vs 产能优化
- 老包装区间固定搭配限制
- 限制了产能分配灵活性

冲突4：生产连续性 vs 产品优先级
- 产品A正在连续生产
- 产品B有紧急优先级约束
- 无法同时满足
```

#### 6.4.2 约束优先级
```
约束优先级（从高到低）：
1. 产线-产品-班组绑定（BC-01）
2. 产线独占产品保证（BC-06）
3. 产品优先级约束（product_priority）
4. 产线禁用约束（line_forbid_time）
5. 区域特殊约束（4.2节）
6. 生产连续性（BC-09）
7. 班组全排产（BC-04）
8. 产能利用率最大化（2.2.1）
9. 班组负荷均衡（2.2.2）

冲突解决原则：
- 优先满足优先级高的约束
- 放松优先级低的约束
- 记录冲突和解决方案
```

### 6.5 换产异常处理

#### 6.5.1 场景：多产品剩余量无法一次换产

**示例**：
```
班次：2025-10-25中班, 030208, pack09
产品A剩余：5000瓶, 标准产能14000
产品B剩余：8000瓶, 标准产能15000
产品C待生产：10000瓶, 标准产能16000

换产验证（使用0.9系数）：
场景1：A完成后换B
- 换产可用产能: (15000 - 5000) × 0.9 = 9000瓶
- B可排产量: min(9000, 8000) = 8000瓶
- 班次总量: 5000 + 8000 = 13000瓶 ≤ 15000 ✓

场景2：B完成后换C
- 换产可用产能: (16000 - 8000) × 0.9 = 7200瓶
- C可排产量: min(7200, 10000) = 7200瓶
- 班次总量: 8000 + 7200 = 15200瓶 ≤ 16000 ✓

场景3：A、B都完成，换产到C（不允许）
- 原因：一个班次最多换产一次
```

**处理策略**：
```
1. 一个班次最多换产一次（最多生产2个产品）
2. 优先完成计划量大的产品
3. 若多个产品剩余量都很小：
   - 选择优先级高的先完成
   - 其他产品顺延到下一个班次
4. 按产品优先级排序决定换产顺序
5. 换产计算必须考虑0.9系数（换产时间损耗）
6. 严格验证：班次总产量 ≤ 标准产能
```

## 7. 排产算法流程

### 7.1 总体流程

```
阶段1：数据校验与预处理
├─ 1.1 校验输入数据完整性
├─ 1.2 构建产线-产品-班组关系图
├─ 1.3 识别独占产品
├─ 1.4 验证约束配置合法性
│   ├─ 验证产线禁用不冲突独占产品
│   └─ 验证产品优先级约束合理性
└─ 1.5 评估产能充足性

阶段2：产品优先级排序
├─ 2.1 识别有 product_priority 约束的产品
├─ 2.2 识别独占产品
├─ 2.3 按交货日期（deliverDay）排序
├─ 2.4 按计划量（bottleTotal）排序
└─ 2.5 生成全局产品排产顺序列表

阶段3：主排产循环（按日期遍历）
├─ 3.1 获取当日可用产线（排除禁用产线）
├─ 3.2 获取当日可用班组（排除已排产班组）
├─ 3.3 按区域分别排产
│   ├─ 老包装区间（固定搭配规则）
│   ├─ 新包装A区（柔性规则，最多1线空闲）
│   ├─ 新包装B区（双班规则）
│   └─ 新包装C、D区（2双2单规则）
├─ 3.4 早班排产
│   ├─ 按产品优先级分配产线
│   ├─ 按班组优先级选择班组
│   ├─ 计算班次计划量
│   └─ 应用区域特殊约束
├─ 3.5 中班排产（同早班流程）
└─ 3.6 检查并处理当日异常

阶段4：连续性与换产处理
├─ 4.1 检查产品生产连续性
├─ 4.2 识别换产场景
│   └─ 产品达到计划量且班次未满
├─ 4.3 计算换产产能（考虑换产损耗）
│   ├─ 换产可用产能 = (标准产能 - 第一产品剩余量) × 0.9
│   ├─ 第二产品可排产量 = min(换产可用产能, 第二产品剩余计划量)
│   └─ 验证：班次总量 ≤ 标准产能
└─ 4.4 调整班次计划量

阶段5：班组柔性调整
├─ 5.1 识别产品完成的产线
├─ 5.2 判断是否可释放班组
│   ├─ 其他产线未打双班
│   ├─ 其他产线有未完成产品
│   └─ 班组在其他产线配置中
├─ 5.3 若无法释放，安排计划量为0的产品
└─ 5.4 更新产线-班组分配状态

阶段6：结果验证与优化
├─ 6.1 验证所有强制约束
│   ├─ BC-01 ~ BC-10
│   └─ 区域特殊约束
├─ 6.2 计算产能利用率
│   ├─ 总体利用率
│   ├─ 各产线利用率
│   └─ 各班组利用率
├─ 6.3 评估班组负荷均衡
│   ├─ 计算均衡度
│   └─ 识别负荷过重/过轻的班组
└─ 6.4 生成预警信息

阶段7：输出排产结果
├─ 7.1 生成排产结果表
├─ 7.2 生成产品完成情况表
├─ 7.3 生成班组负荷统计表
├─ 7.4 生成产能利用率统计
└─ 7.5 生成预警信息表
```

### 7.2 核心排产逻辑

#### 7.2.1 日排产流程
```
对于每个工作日：
  对于每个班次（早班、中班）：
    1. 按区域分组处理产线
    2. 对于每个区域：
       a. 应用区域特殊约束
       b. 获取区域内可用产线和班组
       c. 按产品优先级分配
       d. 选择最优班组
       e. 计算班次计划量
       f. 更新产品状态
       g. 检查是否触发换产
       h. 检查是否触发柔性规则
```

#### 7.2.2 产品分配流程
```
对于每个待排产产品：
  1. 获取产品可用产线列表（按 productLineWeight 排序）
  2. 对于每条产线：
     a. 检查产线是否可用
     b. 检查产线是否有可用班组
     c. 检查是否满足连续性要求
     d. 检查是否满足区域约束
     e. 若通过所有检查，分配到该产线
     f. 若该产线产能不足，考虑下一条产线
  3. 若所有产线都不可用，记录异常
```

#### 7.2.3 班组分配流程
```
对于每条需要班组的产线：
  1. 获取产线可用班组列表
  2. 按优先级排序：
     a. lineCrewPriority（产线对班组偏好）
     b. crewLinePriority（班组对产线偏好）
     c. 当前负荷（负荷轻的优先）
  3. 选择第一个满足条件的班组：
     - 当天未排产（BC-03）
     - 在产线配置中（BC-01）
     - 满足区域特殊约束
  4. 若无可用班组，考虑调整其他产线或报异常
```

### 7.3 区域规则应用

#### 7.3.1 老包装区间排产逻辑
```
固定搭配：pack01+pack02, pack10+pack14
每班次1条线空闲

流程：
1. 确定班次（早班/中班）
2. 选择班组搭配
3. 分配2对班组到3条产线（1条线空闲）
4. 为每个班组选择产品
5. 计算班次计划量
6. 确保固定搭配不被拆分
```

#### 7.3.2 新包装A区排产逻辑
```
柔性规则：同一班次最多1条线空闲

流程：
1. 统计可用班组数量（5个班组，4条线）
2. 优先安排双班（提高利用率）
3. 根据产品需求决定单班或双班
4. 确保不超过1条线同时空闲
5. 若产品完成，触发班组释放规则
```

#### 7.3.3 新包装B区排产逻辑
```
双班规则：2条线必须打双班

流程：
1. 030205分配pack05和pack11（双班）
2. 030206分配pack06和pack13（双班）
3. 优先在030205生产MT0010010082
4. 其他产品按优先级分配
5. 确保2条线全部打双班
```

#### 7.3.4 新包装C、D区排产逻辑
```
2双2单规则：2条双班，2条单班

流程：
1. 统计4条产线的班组分配
2. 确保恰好2条线打双班
3. 其余2条线单班或空线
4. 班组在多条产线灵活分配
5. 验证配置满足2双2单规则
```
